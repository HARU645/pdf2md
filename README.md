# pdf2md

PDF와 **저장한 웹페이지(.html)** 를 AI가 읽기 좋은 마크다운으로 바꿉니다.
사람이 보기 좋은 모양이 아니라, AI가 추론 없이 바로 읽을 수 있는 구조를 목표로 합니다.

## 웹페이지가 있으면 그쪽이 정확합니다

인쇄한 PDF에는 종이 위의 잉크만 남아서, 표가 어디서 시작하고 어느 칸이
어느 열인지를 좌표에서 되짚어야 합니다. 저장한 HTML에는 그 정보가 그대로
있습니다.

| | PDF | 저장한 웹페이지 |
|---|---|---|
| 표 구조 | 좌표로 복원 | 그대로 있음 |
| 병합된 칸 | 빈 칸 비율로 추측 | 빈 칸 그대로 (채우기는 동일) |
| 참고 문단 | "Huom." 이라는 글자로 추측 | `class="huom"` 이 알려줌 |
| 용어 표시 | 글리프 번호로 추적 | `class="kasite"` 가 알려줌 |
| 페이지 넘김 | 전용 규칙 필요 | 문제 자체가 없음 |

그래서 폴더에 `.html` 이 있으면 그것을 쓰고, 없으면 PDF로 처리합니다.
브라우저에서 **Ctrl+S → "웹페이지, HTML만"** 으로 저장하면 됩니다.

## 설치

```
python -m venv venv
venv\Scripts\pip install -r requirements.txt
```

## 쓰는 법

### 화면으로

```
venv\Scripts\streamlit run app.py
```

브라우저에서 `localhost:8511` 을 열면 됩니다. 두 가지 방식이 있습니다.

- **폴더 통째로** — 폴더를 골라 그 안의 PDF를 전부 변환합니다. 경로를 직접
  적어도 되고, `폴더 찾아보기` 로 눌러 들어가며 골라도 됩니다. 폴더에 PDF가
  없으면 한 단계 아래 하위 폴더까지 찾아봅니다.
- **파일 골라서 올리기** — 파일 여러 개를 골라 올립니다. 폴더 경로를
  몰라도 되고, 결과를 ZIP으로 바로 내려받을 수 있습니다.

어느 쪽이든 함께 변환한 문서끼리는 상호참조가 서로 링크로 연결됩니다.
따라서 관련 있는 문서는 한 번에 변환하는 편이 좋습니다.

### USB에 넣어 다니기

```
python build-usb.py --documents D:\...\visk
```

`dist\pdf2md-usb` 폴더가 만들어집니다. 파이썬 본체가 그 안에 함께 들어가므로
**아무것도 설치되지 않은 윈도우 컴퓨터**에서도 `실행.bat` 더블클릭만으로
돌아갑니다. 관리자 권한도, 인터넷도 필요 없습니다.

이 판은 켠 컴퓨터 안에서만 열립니다(`127.0.0.1`). 바깥에 노출되지 않으므로
비밀번호를 묻지 않고, 옆에 있는 `visk` 폴더를 원본으로 알아서 씁니다.

### 명령어로

폴더째로:

```
venv\Scripts\python cli.py "C:\myfiles\pdf" -o "C:\myfiles\markdown"
```

파일만 골라서 (여러 개 나열 가능):

```
venv\Scripts\python cli.py "a.pdf" "b.pdf" -o output
```

## 변환 결과의 특징

- **표의 빈 칸을 채웁니다.** 원본에서 세로로 병합된 칸을 각 행에 복사해서,
  AI가 위쪽 행을 거슬러 올라가지 않아도 한 행만 읽으면 되게 합니다.
- **줄바꿈과 행을 구분합니다.** 원본에서 한 칸의 내용이 두 줄로 감긴 것과
  실제로 다른 행인 것은 겉보기가 같습니다. 표의 괘선, 표제어 칸, 칸 사이 간격
  세 가지를 함께 보고 판단합니다.
- **강조를 지킵니다.** `_rä_**_tt_**_i_` 처럼 기울임 안의 굵은 글씨까지 살립니다.
  문법서에서는 어느 글자가 교체되는지가 핵심 정보입니다.
- **상호참조를 링크로 되살립니다.** PDF 안에 남아 있는 주소를 꺼내
  같은 폴더의 문서면 `./visk-0043.md`로, 아니면 원문 주소로 연결합니다.
- **문서 머리에 정보를 답니다.** 절 번호, 제목, 원문 주소, 계층 경로.
- **목록 파일(`index.md`)을 만듭니다.** 폴더에 뭐가 들었는지, 그리고
  본문이 인용하지만 없는 문서가 무엇인지 정리합니다.

## 검사

변환할 때마다 **원본의 모든 단어가 결과에 남아 있는지** 대조합니다.
하나라도 빠지면 어떤 단어인지 알려줍니다. 표의 칸 수와 강조 표시의 짝도 함께 봅니다.

## 코드를 고칠 때

규칙들이 서로 얽혀 있어서, 한 곳을 고치면 엉뚱한 문서가 조용히 망가집니다.
그래서 검토를 마친 결과를 `tests/golden/`에 정답지로 얼려두었습니다.

```
venv\Scripts\python tests\test_golden.py            # 달라진 곳이 있는지 검사
venv\Scripts\python tests\test_golden.py --accept   # 의도한 변경이면 정답지 갱신
```

**코드를 고친 뒤에는 반드시 검사를 돌리세요.** 결과가 달라졌다면
의도한 것인지 확인한 뒤에만 `--accept` 하시면 됩니다.

정답지는 두 벌입니다. `tests/golden/html/` 과 `tests/golden/pdf/` 로 나뉘어
있어서, 한쪽을 고치다 다른 쪽을 망가뜨리면 바로 드러납니다.

## 다른 종류의 PDF를 추가하려면

`pdf2md/profiles/` 에 파일을 하나 만들면 됩니다.
글자와 표를 읽어내는 엔진은 건드릴 필요가 없습니다.

```
pdf2md/
├─ html_source.py 저장한 웹페이지를 읽음 (구조가 그대로 있는 쪽)
├─ reader.py      PDF에서 글자·괘선·링크를 꺼냄
├─ tagged.py      PDF에 남은 구조 정보를 읽어 표 개수를 대조
├─ inline.py      기울임·굵게·링크를 마크다운으로
├─ tables.py      표를 알아보고 조립
├─ document.py    문서 전체를 조립
├─ verify.py      빠진 글자·구조 검사
├─ convert.py     전체 흐름과 목록 파일 생성
└─ profiles/      문서 종류별 규칙  ← 여기만 늘어남
```

## 알려진 한계

- **§ 64의 표 하나**에서 원래 한 행인 것이 두 행으로 갈립니다.
  원본 PDF에 둘을 구분할 정보가 없습니다(오히려 선이 그어져 있어 두 행처럼 보입니다).
  억지로 고치면 다른 표가 망가지므로 그대로 두고, 쉼표로 끝나는 행은 경고를 띄웁니다.
- **스캔한 PDF는 처리하지 못합니다.** 글자 정보가 없는 이미지 PDF는 OCR이 필요합니다.

## PDF 자체의 구조 정보로 교차 검증

브라우저로 인쇄한 PDF에는 원본 HTML의 구조가 남아 있는 경우가 있습니다
(`<table>`, `<tr>`, `<td>`, 문단, 제목). 이 자료에서는 22개 중 11개가 그렇습니다.

구조 정보가 있으면 **표 개수는 추측이 아니라 사실**입니다. 그래서 변환 결과의
표 개수를 그 값과 대조하고, 어긋나면 알려줍니다. 표가 둘로 쪼개지거나 두 표가
붙어버리는 종류의 오류가 이 검사에 걸립니다.

행 수는 대조하지 않습니다. 줄바꿈은 일부러 한 행으로 합치고 병합된 칸은
채우기 때문에, 원래 개수가 달라지는 것이 정상입니다.

구조 정보로 전면 교체하지 않는 이유는 절반의 문서에만 있기 때문입니다.
그리고 원본 구조가 항상 더 나은 것도 아닙니다 — 예를 들어 한 낱말이 두 줄로
감긴 것을 원본은 별개의 행으로 적어두지만, AI가 읽기에는 한 행으로 합친 쪽이
낫습니다.
